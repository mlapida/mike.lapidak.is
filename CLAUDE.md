# mike.lapidak.is · Claude Context

Personal/professional site for Mike Lapidakis. Static Astro 6 site deployed to Cloudflare Pages.

> **Design rules:** Before adding a component, writing copy, or making a visual change, read `docs/design.md`. It documents voice/tone, type/color/spacing/shadow conventions, hover patterns, the polaroid one-off rule, iconography limits, the iOS Safari safe-area pitfalls, and the no-em-dash rule. Tokens live in `src/styles/global.css`; design *decisions* live in `docs/design.md`.

## Stack

- **Astro 6** (static output, no adapter)
- **Tailwind CSS v4** via `@tailwindcss/vite` Vite plugin
- **@astrojs/sitemap** · auto-generates `sitemap-index.xml` + `sitemap-0.xml` at build
- **@astrojs/rss** · generates `/rss.xml` from the posts content collection at build
- **Leaflet** · GPS mini-map on photo detail pages
- **Content Collections** · photos in `src/content/photos/*.md` and posts in `src/content/posts/*.md`

## Dev Server

astro dev --host 0.0.0.0 --port 4321

Accessible via Tailscale at port 4321. `vite.server.allowedHosts: ['.ts.net']` is set in `astro.config.mjs` so any `*.ts.net` Tailscale hostname is allowed past Vite's host block.

## Photo Sync Pipeline

`scripts/sync-immich.mjs` runs on the same host as Immich (or any host with network access). `scripts/setup-sync.sh` and `scripts/docker-compose.sidecar.yml` provide a one-time Docker sidecar setup for running the sync on a separate host.

1. Fetches all Immich albums ending in `-share`
2. For each new/updated image: downloads original → `sharp().rotate()` (EXIF auto-orient) → resize to 3200px max edge → JPEG 85% → uploads to R2
3. Writes `src/content/photos/{slug}.md` with EXIF-derived frontmatter
4. Removes stale `.md` files for photos removed from Immich albums
5. `git commit && git push` → triggers Cloudflare Pages rebuild

Collection name comes from album description field: `Title: Paris` → collection `"Paris"`. Albums with no description (e.g. `site-share`) produce singles.

**Important:** `sharp().rotate()` must come before `.resize()` to bake in EXIF orientation before computing dimensions. The resulting `imgWidth`/`imgHeight` in frontmatter reflect the correctly-oriented image.

**CDN cache:** R2 images are cached at `assets.lapidak.is` with `max-age=14400`. After a forced re-upload (e.g. `--force`), wait ~4h or purge Cloudflare cache before rebuilding Pages, otherwise Astro's image pipeline fetches stale files.

## Post Image Pipeline

`scripts/migrate-post-images.mjs` is the body-image migration tool: scans `src/content/posts/*.md` for markdown image references to `media.empty.coffee` or `storage.ghost.io`, downloads them to `public/post-images/<slug>/<filename>`, and rewrites the markdown URLs to the local path. Idempotent. Flags: `--dry-run`.

The original feature/hero images were imported via a one-shot script (deleted after use). Future post additions should commit feature images directly to `public/post-images/<slug>/feature.<ext>` and reference them via the `feature_image` frontmatter field.

## Photography Architecture

- Photo grid uses a **justified row layout**: greedy packing algorithm in client-side JS, `data-aspect` attribute on each item computed from `imgWidth`/`imgHeight`. Script runs on load + debounced resize.
- **Critical:** after setting `el.style.width` and `el.style.height`, the justify script must also set `el.style.flexGrow = '0'` · otherwise `flex-grow: 1` (CSS fallback) overrides the explicit width and stretches photos.
- `collectionSlug(name)` utility is exported from `collection/[slug].astro` and imported by `[slug].astro` for breadcrumb links.
- Collection cards on the photography page show a stacked photo preview (3 images with CSS rotation/transform).
- Photo slugs: `photo.id` does **not** include the `.md` extension (Content Layer API with `glob` loader strips it). Any `.replace(/\.md$/, '')` calls are harmless no-ops.

## Posts Architecture

- `/posts/` is paginated via `src/pages/posts/[...page].astro` with Astro's `paginate()` helper at **10 posts per page**. Page 1 lives at `/posts/`, page 2 at `/posts/2/`, etc.
- Year groups (`<h2 class="posts__year">{year}</h2>`) are computed **per page** from `page.data`, so a year that straddles two pages will repeat its header on both.
- Each list row is a grid of `[thumbnail | body]` with a single tag chip in the meta line. Date column dropped in favor of an inline meta line.
- Detail pages render a hero image above the meta/title when `feature_image` is set; absent feature_image falls back to no hero.
- Pager is a plain three-column grid (`prev | counter | next`) · no boxed buttons, just text-style links.
- The `posts__header` uses the same `page-header` pattern as `/work` and `/photography` (border-bottom hairline, large italic title, eyebrow row with the page label and an RSS callout, page-desc max 480px).

## SEO

- `astro.config.mjs` has `site: 'https://mike.lapidak.is'` · enables `Astro.site` and sitemap URLs
- Sitemap excludes `.md` companion routes, `/llms.txt`, and `/rss.xml` via the `filter` option to avoid duplicate-content competition
- `public/_headers` sends `X-Robots-Tag: noindex` on `/posts/*.md` and `/llms.txt` so crawlers drop them while LLMs and direct fetchers still see them
- `Base.astro` accepts an optional `image` prop (post detail pages pass `feature_image`); emits full OG + Twitter Card meta, `author` meta, `rel="sitemap"` link, and `<link rel="alternate" type="application/rss+xml" href="/rss.xml">` for feed auto-discovery
- `public/robots.txt` · `Allow: *` with sitemap pointer
- Page title separator is `·` (middle dot), not the em-dash character. The "no em-dashes in user-facing copy" rule is enforced by `tests/build/meta.test.ts` (sweep test scans every rendered `<title>` for `[—–]`).

## RSS Feed

`/rss.xml` (RSS 2.0) is generated at build by `src/pages/rss.xml.ts` from the published `posts` collection.

- Items: title, link, pubDate (publish_date), description, author, categories from tags (excluding `empty-coffee`/`published`/`draft`/`idea`), and an `<enclosure>` pointing at the feature image when present (mime `image/jpeg` or `image/png`).
- Sorted newest first.
- Auto-discovery via `<link rel="alternate" type="application/rss+xml" href="/rss.xml">` in `Base.astro`.
- Linked from the footer (`Footer.astro`) as plain text "RSS".
- Listed in `llms.txt` under "Optional".
- Excluded from the sitemap.

## LLM-readable Routes

- `/llms.txt` · site summary per llmstxt.org spec, generated from `src/pages/llms.txt.ts` at build (pulls posts + spotlight + RSS reference).
- `/posts/<slug>.md` · markdown source per post via `src/pages/posts/[slug].md.ts`. Strips the duplicate H1+blockquote that's pre-baked in the body, prepends a clean header (title, description, date, read time, tags, source URL).
- Both noindexed for search engines; both fetchable by anyone with the URL.
- Homepage: Person JSON-LD (`schema.org/Person`) with `sameAs` social URLs.
- Photo detail pages: Photograph JSON-LD (`schema.org/Photograph`) with absolute `contentUrl`, GPS `GeoCoordinates`, creator.
- Post detail pages: Article JSON-LD (`schema.org/Article`) with headline, url, datePublished, modified date, image (when `feature_image` is set), author, publisher.
- Photo page descriptions: `"Title · Location · Date · Camera"`.

## Astro Script Rules

- `<script>` tags **must be inside** the `<Base>` component slot · placing them after `</Base>` puts them outside `<html>`
- Scripts run as ES modules (`type="module"`) · automatically deferred, DOM is ready when they execute
- Use frontmatter `import '../styles/global.css'` in layouts, not `<style is:global>@import`
- JSON-LD: use `<script type="application/ld+json" set:html={JSON.stringify(data)} />` inside Base slot
- `getStaticPaths` runs in an isolated scope at build · it cannot reference module-level frontmatter constants. Inline values like `pageSize: 10` directly in the call rather than referencing a const declared above the function.

## Touch / Hover

All `:hover` rules are wrapped in `@media (hover: hover)` sitewide to prevent double-tap issues on touch devices.

## Nav

`position: sticky; top: 0`, solid `var(--color-bg)` background, hairline border-bottom. Plain — no `viewport-fit=cover`, no env-based padding, no JS measurement.

The long-running Dynamic Island bleed bug (page content rendering above the nav, into the safe-area zone) is fixed. The fix is NOT in `Nav.astro` — it's in `global.css`:

1. **`body { background-color: var(--color-bg) }`** — iOS Safari paints the safe-area zone above the layout viewport using **body's** background-color, not html's. Without this, Safari samples rasterised page content during scroll and the bleed appears.
2. **The grain texture lives on `body`'s `background-image` with `background-attachment: fixed`** — NOT as a `position: fixed; inset: 0` pseudo-element. Any fixed-position overlay covering the layout viewport defeats iOS's safe-area paint sampling, which is what made earlier attempts fail.

Don't reintroduce `html::after { position: fixed; inset: 0 }` for any reason. Don't add `viewport-fit=cover` unless you're prepared to handle every safe-area inset yourself; the default is correct here. `env(safe-area-inset-top)` returns 0 on iOS 18.x devices with a Dynamic Island, so don't depend on it. Refs: WebKit "Designing Websites for iPhone X"; zulip/zulip#37367 / #37515 (the Zulip team rediscovered the body-bg requirement). Verified clean on iOS 18.7 + iPhone 17 Pro simulator (iOS 26.4).
